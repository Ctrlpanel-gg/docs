## What the panel discovers

CtrlPanel scans **app/Extensions/Category/Name/**. It expects **NameExtension.php** containing the matching namespaced class, extending **App\Classes\AbstractExtension**. Its only abstract contract is the static **getConfig()** method.

~~~text
app/Extensions/
└── Tools/
    └── HelloWorld/
        ├── HelloWorldExtension.php
        ├── HelloWorldController.php
        └── routes.php
~~~

The route provider loads routes files separately. Settings discovery and payment discovery use the extension helper's validated class list. These are related mechanisms, not a general plugin lifecycle.

<Callout type="warn" title="No automatic install or enable lifecycle">
The provider does not call addon methods named boot, install, enable, or uninstall. There is no general addon manager in the inspected release. A setting named enabled only affects a feature if your code actually checks it.
</Callout>

## Naming rules

Both directory segments must start with an ASCII letter and contain only letters, digits, or underscores. The class and filesystem casing must match. Keep extension names unique across categories: name-based lookup reports ambiguity when multiple extensions share a name.

## Choose the right integration

An HTTP client integration belongs in the [API reference](/docs/api). A visual override belongs in [theming](/docs/theming). An installed extension runs trusted PHP inside the panel, so its code has access to the application and needs review before deployment.
